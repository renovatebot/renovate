The `gemspec` manager extracts Ruby runtime and development dependencies declared with `add_dependency`, `add_runtime_dependency`, and `add_development_dependency` in `*.gemspec` files.

For example:

```ruby
Gem::Specification.new do |spec|
  spec.add_dependency 'rack', '~> 3.1'
  spec.add_runtime_dependency 'rails', '>= 7.0', '< 8.0'
  spec.add_development_dependency 'rspec', '~> 3.13'
end
```

### Lock file maintenance

When a sibling `Gemfile` uses the [`gemspec` directive](https://bundler.io/guides/creating_gem.html) and a sibling `Gemfile.lock` exists, Renovate refreshes the lock file with Bundler after changing a constraint.
If the `Gemfile` has no `gemspec` directive, or there is no `Gemfile.lock`, then Renovate only updates the `*.gemspec` file.

### Limitations

A `.gemspec` file is a Ruby program, so fully evaluating one requires a Ruby interpreter.
That is out of scope for Renovate, so this manager parses the file statically instead.
In practice nearly all `.gemspec` files declare their dependencies in the conventional literal form shown above, but Renovate skips declarations that it cannot read statically.

Renovate does _not_ support dependencies generated by loops:

```ruby
%w[core model controller].each do |variant|
  spec.add_dependency "my-framework-#{variant}", '~> 1.0'
end
```

Renovate does _not_ support conditional dependencies, and extracts the declarations from _all_ branches, regardless of which branch Ruby would take:

```ruby
if RUBY_VERSION >= '4.0'
  spec.add_dependency 'foo', '~> 2.0'
else
  spec.add_dependency 'foo', '~> 1.0'
end
```

Renovate also does _not_ support version constraints built from variables or interpolation, and skips those dependencies:

```ruby
spec.add_dependency 'foo', "~> #{FooVersion::MAJOR}.0"
```

If your `.gemspec` file uses any of these patterns, then update those dependencies manually.
